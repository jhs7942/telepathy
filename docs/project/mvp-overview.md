# 텔레파시 MVP 프로젝트 개요

## 목표

텔레파시 웹 서비스의 기술스택과 데이터베이스 구조를 개선하고, 하나의 코드 기반으로 웹과 Android 앱을 함께 운영할 수 있는 구조를 만든다.

## 기간

QA와 서비스 재배포를 포함해 전체 개발 기간은 **3개월**로 한다.

## 범위

1. 실제 운영 코드를 분석한다.
2. Next.js와 TypeScript 기반 웹 화면을 단계적으로 구현한다.
3. Node.js JavaScript를 Node.js TypeScript로 전환한다.
4. 데이터베이스를 정규화하고 기존 데이터를 이전한다.
5. 키워드를 기준으로 상대를 연결하는 랜덤 채팅 구조를 설계하고 구현한다.
6. 회원 로그인과 비회원 로그인을 구현한다.
7. 웹 사용자 화면을 React Native WebView 기반 Android 앱에서 재사용한다.
8. QA를 진행하고 서비스를 재배포한다.

## MVP 제외 범위

결제, 메가폰, 신고, 관리자, 알림 기능은 이번 MVP에 포함하지 않는다. 사용자 반응과 운영 필요성을 확인한 뒤 후속 단계에서 우선순위를 다시 판단한다.

## 목표 기술 구조

- 웹 서비스는 Next.js와 TypeScript를 사용해 개발·운영한다.
- 서버 API와 실시간 기능은 NestJS와 TypeScript로 운영한다.
- 웹과 서버가 함께 쓰는 데이터 계약은 공통 모듈에서 관리한다.
- Android 앱은 React Native WebView로 웹 사용자 화면을 재사용한다.
- 데이터는 Supabase PostgreSQL에 저장하고, Redis는 키워드 기반 랜덤 매칭의 동시성 제어가 필요한 시점에 도입한다.

웹 workspace는 Next.js App Router 기반으로 전환했다. 이제 이 기반 위에서 키워드 기반 랜덤 채팅과 회원·비회원 로그인 화면을 우선 구현하고, 화면과 기능을 단계적으로 확장한다.

## 계획 문서

상세 계획은 Linear 프로젝트의 Documents 탭에서 관리한다. 각 이슈에는 실제로 실행할 수 있는 작업 단위만 담는다.

- **기술스택 마이그레이션 2차 최종 계획안**: 범위, 아키텍처, 완료 조건을 정리한 마스터 계획
- **마이그레이션 역할 분담 1차안**: PM과 개발자의 역할 경계
- **운영 배포 전 프론트엔드 성능 점검**: 현재 측정 결과와 개선 계획의 기준선

## 작업 관리 방식

- 모든 작업은 Linear 이슈로 만든다.
- 이슈 식별자를 브랜치명으로 사용한다. 예: `TEL-12`.
- 이슈에는 실행 단위만 기록하고, 전체 범위와 판단 기준은 계획 문서에서 관리한다.
- 작업이 끝나면 GitHub Pull Request를 스쿼시 머지하고, 해당 Linear 이슈를 완료 상태로 바꾼다.
