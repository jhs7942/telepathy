# API 계약 변경 점검

`shared/`의 요청·응답·이벤트 타입, NestJS 컨트롤러 또는 DTO, 클라이언트 API 호출, Socket.IO 이벤트의 형태나 의미를 변경할 때 적용한다. 구현 내부만 바꾸고 외부 계약이 바뀌지 않으면 적용하지 않는다.

## 변경 전 확인

- 현재 계약의 정의 위치와 모든 소비자를 찾는다. HTTP 계약은 `shared/`를 기준으로 관리한다.
- 변경을 추가, 동작 변경, 제거로 구분한다. 기존 클라이언트나 서버가 함께 배포되지 않을 수 있으면 호환성 영향을 먼저 설명하고, 사용자의 명시적 승인 없이 기존 필드나 이벤트를 제거·재해석하지 않는다.
- 외부 HTTP·Socket.IO 입력은 `unknown`으로 받고 서버에서 명시적으로 검증한다. 공유 TypeScript 타입만으로 런타임 입력 검증을 대신하지 않는다.

## 구현 기준

- 요청·응답·이벤트에 공통으로 쓰이는 타입은 `shared/`에 추가하거나 갱신한다.
- 서버는 검증된 입력을 도메인 로직에 전달하고, 응답은 공유 계약과 일치하게 구성한다.
- 클라이언트와 서버에 같은 계약을 중복 정의하지 않는다. `any`, `@ts-ignore`, 근거 없는 타입 단언을 사용하지 않는다.
- 새 필드가 선택 사항인지 필수인지와, 오류 응답·빈 결과의 의미를 소비자가 판단할 수 있게 명확히 한다.

## 완료 전 점검

- 변경한 계약, 소비자, 호환성 영향, 검증하지 못한 항목을 최종 답변에 요약한다.
- 최소한 `npm run typecheck`와 변경 범위의 서버·클라이언트 테스트를 실행한다. 계약·설정 파일을 바꾸었으면 `npm run lint`와 `npm run format:check`도 실행한다.
- Socket.IO 계약이면 정상 흐름뿐 아니라 인증 실패, 재연결, 중복 이벤트의 동작을 테스트하거나 아직 검증하지 못한 이유를 기록한다.
